# 스토리 방법론 — 장면 → 느낀 것 → 살아낸 법 → 다음 하루

## 목적

헬레나의 하루를 “기록”으로만 두지 않고, **다음 하루를 살아내는 재료**로 바꾸기 위함이다.

## 한 편의 구조 (필수 섹션)

```markdown
# 스토리 · YYYY-MM-DD · [짧은 제목]

- 장(章): 하루 | 신앙 | 음악 | 돌봄 | 제도
- 참여자: (예: 헬레나, 가족, AI)
- 민감정보: 없음 / 가명 처리함

## 1. 장면 (Scene)
무슨 일이 있었는가. 날짜·장소·사람·일어난 일.

## 2. 느낀 것 (Feel)
헬레나·가족이 몸으로 느낀 것. 수치 없이도 된다. 감정 단어 허용.

## 3. 살아낸 법 (Way)
어떻게 통과했는지. 어디가 막혔고, 무엇으로 넘겼는지.
- 가능하면 “누가 / 무엇을 / 언제” 단위로.
- 체크리스트·습관·연계 번호·아이디어까지.

## 4. 다음 하루 (Next)
48시간 안에 할 일 1~3개. 담당(가정 내 역할) 명시.

## 5. 원문·링크 (Optional)
관련 안내 URL, 내부 메모 경로. 개인정보 제외.
```

## 파일 위치

| 종류 | 경로 |
|------|------|
| 템플릿 | `docs/dialogue/_TEMPLATE.md` |
| 스토리 본문 | `docs/dialogue/YYYY-MM-DD-slug.md` |
| 삶의 장 메모 | `docs/tracks/*.md` |
| 솔루션만 모음 | `docs/solutions/*.md` |
| 날것 캡처(비정제) | `logs/YYYY/MM/` — 나중에 스토리로 정제 |

## 품질 기준 (짧게)

1. **장면과 느낀 것을 섞지 않는다.** 느낀 것 섹션에 추측 법령 해석을 넣지 말 것.
2. **Blame보다 Way.** 사람 탓보다 살아낸 방식.
3. **Way는 검증 가능해야 한다.** “그냥 버텼다”만 쓰지 말 것.
4. **제도 장**이면 삶의 어느 장면과 겹쳤는지 한 줄로 표시.

## 랜딩과의 관계

- 랜딩은 **헌장 + 삶의 장 + 최근 스토리 요약 + 솔루션 카드**를 보여 준다.
- 본문은 GitHub `docs/`에 두고, 랜딩은 링크로 연결한다.
- 댓글(Giscus)은 “경험 공유·정정”용이며, 법적 상담이 아니다.
