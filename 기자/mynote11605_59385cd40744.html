지식공장

Breakthrough · 2026-08-10

루프백 발견 — "콘텐츠 공장"에서 "사이버네틱 시스템"으로

일방향 파이프라인 → 폐쇄 루프.
발행된 콘텐츠를 LLM이 다시 읽고 평가할 수 있다는 실증.

발견 — 루프백(Loopback)이 실제로 작동한다

오늘까지의 생태계는 일방향이었다:

LLM 대화 → 캡처 → .md → HTML → 텔레그램 → 티스토리 → RSS → GitHub → Pages. 끝.

그런데 Claude Code가 실제로 티스토리 URL을 fetch해서 파싱한 순간, 반대 방향이 증명되었다:

이게 왜 근본적인가

차원루프백 이전루프백 이후
시스템 유형일방향 파이프라인사이버네틱 폐쇄 루프
콘텐츠 상태발행 = 종료 (죽은 기록)발행 = 검증 시작 (살아있는 자산)
품질 기준"내 느낌에 좋다"LLM이 구조·SEO·연결성 측정
버전 업그레이드감으로 결정측정된 지표 기반
피드백 루프없음발행→파싱→평가→개선 반영
확장성내가 직접 읽어야 함LLM이 6채널 전부 자동 진단

실제로 증명된 것

1. 티스토리 = 크롤링 가능
mynote11605.tistory.com이 공개 URL로 fetch 가능. og:description, title 등 메타데이터 전부 수집됨. 6개 글 제목·구조 단번에 파싱 완료.
2. SEO 평가 가능
메타데이터가 잡히니까 "이 블로그가 SEO적으로 잘 짜였는지" LLM이 진단 가능. 키워드 커버리지·구조화·가독성 전부 측정 대상.
3. 편집적 판단 가능
6개 글의 제목·구조를 보고 "이게 시리즈로 잘 이어지는지" 같은 판단을 LLM이 수행. 콘텐츠 전략 평가가 자동화됨.
4. GitHub Pages도 동일
Pages URL도 fetch 가능. 정방향(제작 시 소스 참조) + 역방향(발행물 평가)이 동일한 fetch 메커니즘으로 작동.

오늘의 다른 결정과 정확히 맞물리는 지점

오늘의 결정방향루프백과의 연결
GitHub Pages 소스코드 파싱정방향 (제작 시 입력)만들 때도 소스 참조 + 만든 다음에도 결과물 평가 = 동일한 fetch 메커니즘으로 양방향
RSS Sync 5레포 1:1역방향 (백업)RSS가 티스토리를 GitHub로 가져오는 것 자체가 루프백의 전제 조건. GitHub에 있어야 LLM이 fetch 가능.
Paste Pipeline v5.1 (.txt)정방향 (발행)발행이 정확해야 평가가 의미 있음. 품질 게이트가 루프백의 입력 정확도를 보장.
측정 가능한 기준으로 버전 업그레이드피드백루프백이 측정값을 제공해야 버전 업그레이드가 감이 아니라 데이터 기반이 된다.
2계층 양방향 브릿지양방향Paste(내부→외부) + RSS(외부→내부)에 루프백이 3번째 브릿지로 추가됨: 평가(외부→LLM→내부).
핵심 통찰: 루프백은 단순한 "기능 추가"가 아니라 시스템의 존재론적 전환이다. "콘텐츠 공장"(일방향 파이프라인) → "자기 인식 시스템"(폐쇄 루프). 이제 이 생태계는 스스로를 읽고, 평가하고, 개선할 수 있다.

이것으로 가능해지는 것들

자동 품질 대시보드
6채널 × SEO 점수·구조화 점수·가독성 점수. 매주 LLM이 재파싱해서 주간 품질 리포트 자동 생성.
콘텐츠 갭 분석
5개 티스토리 전부 파싱 → "이 주제는 다뤘는데 저 주제는 비었네" 자동 감지 → 다음 콘텐츠 기획에 반영.
시리즈 완결성 검사
"Part 1~5 중에 3이 빠졌네" 같은 구조적 누락을 LLM이 자동 발견. 사람이 일일이 확인할 필요 없음.
버전 업그레이드 트리거
"구조화 점수가 70→85로 올랐네 → V13" 같이 측정값 기반 자동 버저닝 가능.
크로스 채널 분석
Phone·Tech·Faith·Piano·Metalcare 5채널 전부 파싱 → "채널 간 연결이 약한 지점" 크로스 레퍼런싱 진단.
자기 수정 루프
궁극적 목표: 평가 → 진단 → 자동 수정 PR → Boss 승인 → 발행. 사람은 감독만.
